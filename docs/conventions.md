# 코딩·작업 규칙

## C#

- 네임스페이스·클래스·메서드: PascalCase. 지역 변수·매개변수: camelCase. private 필드: `_camelCase`.
- 서버 게임 로직은 룸 단위 `JobSerializer`로 직렬 실행한다. 룸 상태를 다른 스레드에서 직접 건드리지 않는다.
- 클라: 매니저는 `Managers`를 통해 접근한다(기존 구조 유지). `Update`에서 매 프레임 할당(LINQ, new)을 피한다.
- 클라·서버에 같은 이름의 데이터 클래스가 있을 때(예: `Data.Contents.cs`) 한쪽만 고치지 않는다.
- 주석은 "왜"만 적는다. 기획 용어(원혼, 삼천도, 저승)는 한글 그대로 주석·문서에 써도 된다.

## 생성 코드 (손대지 않음)

- `Protocol.cs`, 패킷 매니저 등 PacketGenerator/protoc 산출물은 직접 수정하지 않는다. 원본(`Protocol.proto`, `PacketFormat.cs`)을 수정하고 재생성한다.

## 커밋

- 사용자가 요청할 때만 커밋한다.
- 메시지는 한국어, 한 커밋 한 목적(기능 / 테이블 / 리소스 / 설정을 섞지 않는다).
- xlsx를 바꾸면 변환된 JSON을 같은 커밋에 포함한다. Unity 자산은 `.meta`와 함께.
- 비밀값·로컬 설정(`UserSettings`, `Library`, `Temp` 등)은 커밋하지 않는다(`.gitignore` 준수).
