# 테이블 변환기 설계 (TableConverter)

`Table/MasterTable.xlsx` → JSON + C# 데이터 클래스. 규약 자체는 [data-tables.md](data-tables.md), 여기는 **변환기를 어떻게 만들 것인가**다. (설계 단계 — 구현 전)

## 목표

1. 기획자(사용자)가 xlsx만 고치고 명령 한 번으로 서버·클라가 쓰는 JSON을 갱신한다.
2. **데이터 클래스도 자동 생성**해서 시트를 추가할 때 클라·서버 클래스를 손으로 맞추지 않는다.
3. 잘못된 데이터(ID 중복, 깨진 참조, 없는 stringID)는 변환 단계에서 **셀 위치와 함께** 잡는다.
4. 같은 입력이면 같은 출력(결정적). git diff에는 실제로 바뀐 값만 나온다.

## 형태

- `Tools/TableConverter/` — .NET 10 콘솔 프로젝트. xlsx 읽기는 ClosedXML(MIT) 등 라이선스가 허용하는 라이브러리.
- 실행: `dotnet run --project Tools/TableConverter` (옵션 아래). Unity 에디터 메뉴(`Tools > Table > Export`)는 이 명령을 호출하는 얇은 래퍼로 나중에 추가한다.
- xlsx가 Excel/LibreOffice에 열려 있어도 읽히도록 `FileShare.ReadWrite`로 열거나 임시 복사본을 읽는다.

| 옵션 | 동작 |
|---|---|
| (없음) | 전체 변환 후 출력 파일 갱신 |
| `--check` | 파일은 쓰지 않고, 현재 출력과 다르면 종료 코드 1 (빌드/커밋 전 검증용) |
| `--sheet <이름>` | 해당 시트만 변환 (디버그) |

## 입력 해석 (data-tables.md 규약 그대로)

1. 시트 이름이 `#`로 시작하면 건너뛴다. `strings`는 별도 처리.
2. 2행 키를 필드명으로, 1행의 `|float`를 타입 힌트로 쓴다.
3. 키가 `#`로 시작하는 컬럼, A열이 `//`인 행, 완전히 빈 행은 건너뛴다.
4. 컬럼 타입 결정 순서: ① `|float` → `float` ② 그 외 전 셀이 정수 → `int` ③ 그 외 → `string`. 키가 `<List>`로 끝나면 `|` 구분 `List<요소타입>`(요소는 같은 규칙으로 판정).
5. 빈 셀 → 기본값(0 / "" / 빈 리스트).

> 주의: ②는 데이터에 의존하므로 소수 컬럼이 우연히 전부 정수가 되어도 `|float` 힌트가 있으면 안전하다. 힌트 없는 소수 컬럼을 발견하면 **오류로 중단**하고 `|float` 추가를 요구한다(조용히 string이 되는 것 방지).

### 키(Key) 결정

- 기본: 첫 데이터 컬럼(보통 `xxxID`)이 유일 키.
- 예외(복합 키 등)는 `Tools/TableConverter/tables.json`에 선언한다:

```json
{
  "characterLevel": { "key": ["group", "level"] },
  "spirits": { "refs": { "skillIDs": "spiritSkills" } },
  "regions": { "stringKeys": ["name"] }
}
```

- `refs`: 이 컬럼의 값(리스트면 각 요소)이 가리키는 시트. 존재하지 않으면 오류.
- `stringKeys`: 이 컬럼 값이 `strings`의 stringID여야 함(없으면 오류).
- `tables.json`에 없는 시트도 변환은 된다(검증만 약해짐). 검증 규칙은 시트를 추가할 때 같이 채운다.

## 출력

### JSON — `Client/Assets/Resources/Data/<SheetName>.json`

모든 시트 공통 래퍼 `{ "rows": [ ... ] }`. 제너릭 로더 하나로 읽을 수 있고 Unity `JsonUtility`와 Newtonsoft 모두 읽는다(필드는 camelCase 공개 필드, 숫자는 숫자 타입).

```json
{ "rows": [ { "spiritID": 8501, "role": 1, "attackRate": 0.75, "skillIDs": [85011, 85012] } ] }
```

- 파일명: 시트명 첫 글자 대문자(`spiritSkills` → `SpiritSkills.json`).
- UTF-8(BOM 없음), LF, 들여쓰기 2칸, 행 순서는 시트 순서.

### C# — 클라·서버 각각 생성

- 위치: `Client/Assets/Scripts/Data/Generated/Tables.g.cs`, `Server/Server/Data/Generated/Tables.g.cs` (같은 내용, 네임스페이스 `Table`).
- 시트당 행 클래스 `SpiritRow` + 키 룩업을 가진 `SpiritTable`.
- 파일 상단에 `// <auto-generated> 수정 금지 — TableConverter가 생성` 표기. 손대지 않는다.
- 공통 `TableManager`(손으로 작성)가 시작 시 JSON들을 읽어 `Dictionary`를 만들고, 실패하면 파일·행을 로그로 남기고 종료한다. 기존 `DataManager`의 역할을 대체한다.

### strings

- 출력 `Strings.json`: `{ "rows": [ { "id": "Region_61101", "kr": "...", "en": "...", "cn": "...", "tw": "...", "jp": "..." } ] }`
- `#`로 시작하는 언어 컬럼(DEU 등), `//` 행은 제외. 클라는 설정된 언어 컬럼을 조회하고, 비어 있으면 KR로 대체.
- 언어가 늘어 파일이 커지면 언어별 파일(`Strings.KR.json` …)로 쪼갠다(지금은 하지 않는다).

## 검증 (오류 형식: `시트!셀 — 메시지`, 하나라도 있으면 출력 쓰지 않음)

| 검사 | 예 |
|---|---|
| 키 중복 | `spiritSkills!B14 — skillID 85012 중복 (B9와 동일)` |
| 타입 변환 실패 | `spirits!K5 — 정수가 아님: "1.5" (|float 필요?)` |
| 참조 깨짐 | `spirits!T3 — skillIDs 85019 가 spiritSkills에 없음` |
| stringID 누락 | `regions!E7 — Region_61199 가 strings에 없음` |
| 경고(출력은 함) | 힌트 없는 빈 컬럼, 사용되지 않는 stringID |

## 코드 변경 범위 (구현 시)

- 새 파일: `Tools/TableConverter/*`, `Tables.g.cs`(생성물), `TableManager.cs`(클라·서버 각각 얇게).
- 수정: 서버 `Program.cs` 시작 시 `TableManager.Load()` 호출, `config.json`의 `dataPath` 재사용.
- 레거시 교체: `DataManager.StatDict` → `characterLevel`, `SkillDict` → `spiritSkills` 기반으로 `Monster.cs`, `GameRoom.cs`, `ClientSession.cs`의 사용처를 옮긴 뒤 `StatData.json`/`SkillData.json`과 무기 계열 시트를 삭제한다. (사용처는 현재 3곳)

## 구현 상태

- **1단계 완료 (2026-11-22)**: `Tools/TableConverter/` (ClosedXML 0.105.1, MIT). `spirits`·`spiritSkills`·`characterLevel` 3개 시트를 JSON으로 변환. 같은 입력 두 번 실행 시 출력 바이트 동일 확인, 행 수(5/20/65) 일치.
- 실행: `dotnet run --project Tools/TableConverter` (저장소 어디서든, `CLAUDE.md`를 찾아 루트를 잡는다). 옵션: `--sheet <이름>`(반복 가능, 기본 3개), `--xlsx <경로>`, `--out <폴더>`.
- 내용이 같으면 파일을 다시 쓰지 않는다(mtime 유지). 오류가 하나라도 있으면 아무 파일도 쓰지 않는다.
- 구현된 규칙: `#` 컬럼·`//` 행·빈 행 제외, `<List>` 배열, `|float` 힌트, 정수/문자열 자동 판정(소수가 힌트 없이 섞이면 오류), 중복 키 오류, 빈 셀 기본값.
- **2단계 구현 완료, 클라 Unity 컴파일은 미확인**: 변환기가 C# 데이터 클래스·테이블·`TableManager`를 생성한다 (`Server/Server/Data/Generated/Tables.g.cs`, `Client/Assets/Scripts/Data/Generated/Tables.g.cs`, 내용 동일). 시트당 `<Sheet>Row`(필드 = JSON 키), `<Sheet>File`(`rows`), `<Sheet>Table`(키 조회). 키는 기본 첫 컬럼, 예외는 `Tools/TableConverter/tables.json`의 `key`(예: `characterLevel` = `(group, level)`). 키 중복은 변환 단계에서도 오류로 잡는다. `--sheet`로 일부만 변환할 때는 C# 생성을 건너뛴다.
  - 서버: `FileTableReader`(Newtonsoft) + `Program.Main`에서 `TableManager.LoadAll` 호출, 실패 시 메시지 출력 후 종료. 빌드 성공, 기동 확인, 별도 테스트로 조회 값(`spirits` 5 / `spiritSkills` 20 / `characterLevel` 65, 복합 키, 없는 경로 오류 메시지) 확인.
  - 클라: `ResourcesTableReader`(Resources + `JsonUtility`) + `DataManager.Init`에서 `TableManager.LoadAll` 호출. C# 9 + Unity 스텁으로 별도 컴파일은 통과했지만, **실제 Unity에서의 컴파일·`.meta` 생성·`JsonUtility` 역직렬화는 아직 확인하지 못했다**(Pipeline 패키지가 없어 CLI로 Editor를 구동할 수 없음). Unity를 열어 컴파일 오류가 없는지, Play 시 로딩 로그가 정상인지 확인해야 한다.
- 미구현: 아래 3~5단계.

## 구현 순서

1. ✅ 시트 읽기 + 타입 판정 + JSON 출력 (`spirits`, `spiritSkills`, `characterLevel` 3개로 시작). 출력 결정성 확인.
2. C# 클래스 생성 + `TableManager`(서버 먼저, 클라는 Unity 컴파일 확인).
3. `tables.json` 기반 검증(키·참조·stringID). 전 시트로 확대.
4. `strings`.
5. `--check` 모드, 레거시 로더 교체·삭제, 에디터 메뉴 래퍼.

## 열린 결정

- **클라이언트 JSON 라이브러리**: 서버는 Newtonsoft. 클라에서 `JsonUtility`(의존성 없음, `Dictionary` 미지원이라 래퍼 구조에 적합)를 쓸지 Newtonsoft(Unity 패키지)를 쓸지 — 현재 클라가 쓰는 쪽에 맞춘다.
- **enum 생성**: `role`, `targetType` 같은 정수 코드를 `#타입 정의` 시트에서 C# enum으로 생성할지(코드 가독성↑, 시트 형식 합의 필요). 1차 구현에서는 정수 그대로 두고 나중에 도입을 제안한다.
- **생성된 `.g.cs`·JSON 커밋 여부**: 둘 다 커밋하는 것을 기본으로 한다(xlsx 없이도 빌드·실행 가능).
