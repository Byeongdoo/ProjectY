# 구현 로드맵

원칙: **필요한 시점에 필요한 것만** 만든다. DB·웹서버는 4단계 이후.

| 단계 | 목표 | 완료 기준 |
|---|---|---|
| 0. 기반 | 테이블 변환기(xlsx→JSON), 규약 확정, 현재 클라·서버 빌드·실행 확인, 레거시 정리(무기 계열 시트 4개, `StatData`/`SkillData` JSON → 새 로더로 교체 후 삭제) | MasterTable 수정 → JSON 갱신 → 서버·클라 로딩 성공 |
| 1. 클라 프로토타입 | 8방향 칸 이동, Space 평타, 숫자키 스킬+방향키 대상 선택 (플레이스홀더 아트) | 서버 없이도(또는 로컬 서버로) 조작·전투 흐름이 동작 |
| 2. 서버 연동 | 입장·이동 동기화, 서버 권위 이동/전투 판정 | 두 클라가 같은 룸에서 서로의 이동·공격을 본다 |
| 3. 삼천도·파티·저승 | 삼천도 채널(시설은 나루터 중심으로 최소화), 파티·큐·원혼 배정, 나루터 원혼 선택, 4인 던전 한 판(구간 → 불씨 → 보스방, 위협·혼절·부활·개인 드랍) | 4인이 로비에서 모여 던전을 클리어 |
| 4. 영속성 | **여기서 DB 도입**: 계정·캐릭터·인벤토리 저장 | 재접속해도 캐릭터 상태 유지 |
| 5. 웹서버 | 로그인/인증, 패치·공지, 랭킹 등 필요한 것만 | 인증 후 게임 서버 접속 |
| 6. 이승 콘텐츠 | 퀘스트·대화·퍼즐, 챕터 확장, 이승↔저승 연결 | 한 챕터 루프(이승→죽음→삼천도→저승→귀환) |

- 이승(싱글)은 **서버 없이 클라 단독**이다. 따라서 이승 콘텐츠(6단계)는 서버 단계와 독립적으로 앞당겨 진행할 수 있다. 이승 진행도는 **로컬 세이브**(확정). 이승↔삼천도 전환 시 서버가 클라 제출값을 검증하는 범위는 2단계에서 정한다. 4단계(DB)에서 서버 저장 전환 여부를 재검토한다.
- 단계 순서·범위는 진행하며 사용자와 조정한다. 다음 단계로 넘어가기 전에 완료 기준을 확인한다.
- 아트는 각 단계에서 필요한 만큼만 Codex에 요청한다([art-pipeline.md](art-pipeline.md)).
- 현재 위치: 0단계 (서버 .NET 10 업그레이드까지 완료, 클라/서버 기본 골격 존재).
